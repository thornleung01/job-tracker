# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users
One person running a job search, on their own Windows PC, plus a few invited people using the hosted edition in their own browser. They open the app daily or weekly to see where each application stands (applied, heard back, assessment, interview, offer, rejected), log dated steps (each can carry a short note), and read the Statistics page. They also show it to other people (screenshots, demos), so it has to hold up as a presentation piece as well as a daily tool.

## Product Purpose
A private job-application tracker that runs on the user's own device (a Windows PC for the local edition, a browser for the hosted edition). It reads Gmail and Outlook (read-only by default; sending a reply is an opt-in permission per account, used only when the user writes and sends one), recognises application emails with editable rules (no AI reads the mail; AI is opt-in for resumes, with the person's own key), and turns them into a list of applications with a stage, a history, and a Sankey flow of where applications went. Success is that the user never has to search an inbox to know the status of an application.

## Positioning
Everything comes from the user's own email and stays on their own device (their PC, or their browser's storage in the hosted edition): no account with us, no cloud copy, no AI reading the mail (the optional AI for resumes uses the person's own Anthropic key and sees only the resume text they choose to send). In the hosted edition, logging in with Google or Microsoft only identifies the user (account ID and email address) and grants read access to their own mailbox. Each application's history is the real emails behind it, and every email can be opened.

## Operating Context
Two editions share one visual system (see DESIGN.md).
- **Local edition** (`jobtracker/`): FastAPI + SQLite + server-rendered Jinja templates, no JavaScript framework, bound to 127.0.0.1 with no login of its own (it is meant for a computer only the user uses). Reads mail with desktop-app OAuth clients; tokens are encrypted with Windows DPAPI (plain text readable only by the user on other systems). Syncs from the CLI or a scheduled task.
- **Hosted edition** (`web/`): a static TypeScript app served from GitHub Pages at https://thornleung01.github.io/job-tracker/. There is no server. Login is Google or Microsoft OAuth in the browser (Microsoft: authorization code + PKCE; Google: Identity Services token client, with the access token checked with Google to learn who logged in), mail is read directly from Gmail and Microsoft Graph, and all data stays in IndexedDB on the user's device, namespaced per logged-in user. One click on Continue with Google or Continue with Microsoft logs in and connects the mailbox together, and the first sync starts by itself. Access tokens live in memory only, so after a reload the user logs in again. Sync happens while the app is open; there is no background sync. Access is limited to people on the Google Cloud consent screen's test-user list (an in-app allowlist would be cosmetic, since nobody can see anyone else's data).

Used on desktop mostly, sometimes on a phone-width window. The local edition works offline (no CDNs), so any typeface must be served from the project; the hosted edition bundles its assets the same way.

## Capabilities and Constraints
- Hosted only: Resume (a master resume read from a PDF, Word or text file or pasted, with jobs, titles, bullets, skills and schools recognised, resume versions, cover letters, print or save as PDF, where a resume prints as a one-page classic resume with a fit status), a "Resume sent" choice on every application with a list filter, an optional Resume column and bulk Set resume, the job posting text kept on an application, search that reads the posting and the cover letter, and "Sent: …" on Coming up and the calendar. Resumes, cover letters and posting text stay in the browser, are in Export data and the backup file, and wait in Recently deleted for 30 days like applications. An AI card in Settings holds the person's own Anthropic key, locked on the device with a passphrase, and Convert on the Resume page turns an uploaded resume into the owner's template, which the person checks and accepts before anything is saved. They stay in the browser unless the person chooses Convert, which sends the shown resume text to Anthropic with their own key.
- Pages, both editions: Applications (sortable, filterable list; rows expand in place to log dated steps, each with an optional note, and to read emails), Statistics (headline numbers, applications per week against the weekly goal, how fast companies reply, what is waiting, the Sankey funnel and the reply rate by month, each with a table equivalent; hosted edition only, the local edition has the funnel; Save as image, Copy image and Share make a picture of the funnel that shows totals only), People, Resume (hosted edition only: a master resume read on the device, standalone resume versions to choose per application, and cover letters), Needs review (emails the rules were unsure about), Application detail, Settings (accounts and sync, appearance; deliberately simple, with no email-filter rules). Notes imported from an older copy of the data still show in an application's history.
- Local only: Jobs and Profiles. Hosted only: Log in, the `#/setup` guide, and in Applications a "Coming up" list of interviews in the next week, a List and Calendar toggle (a month of interviews, applied dates, offer deadlines, follow-ups and logged steps, with an agenda list on a phone), a follow-up nudge for applications quiet for 7 to 29 days and a "No reply in 30 days" tag after that, a "Draft follow-up" button that opens an unsent message in the person's own Gmail or Outlook, Add to calendar (`.ics` files for interview days), search that also reads email text, notes and steps, saved views, a weekly goal, a Compare offers card, "Add several links", keyboard shortcuts, an optional Rounds column, selecting several rows to set a stage or delete, offer salary and decision deadline at the Offer stage, and in Settings, Recently deleted and Your data (export JSON or CSV, import, backup reminders, an optional backup file, whether the browser will keep the data).
- Appearance settings are user-facing and must keep working: theme (system/light/dark), accent color, density (comfortable/compact), corners (soft/sharp), list columns, default Statistics period.
- Local edition: behavior, copy facts, URLs, form names, and data are not changing; the Wealthsimple restyle is visual only.
- The hosted edition doesn't have replying from the app, the Jobs tab (Adzuna, Windows pop-ups), multiple profiles or scheduled background sync. Coming up, the calendar view, follow-up nudges and drafts, Add to calendar, saved views, the weekly goal, Compare offers, Add several links, keyboard shortcuts, Recently deleted, backup reminders and the backup file, offer details, selecting several rows, the duplicate warning, the Rounds column and CSV export are hosted-edition only.
- Hosted edition, mail stays read-only. "Draft follow-up" only opens a new unsent message in Gmail or Outlook with the text in the link: the app never sends it and asks for no send permission. Add to calendar writes a file on the device and sends nothing.
- Hosted edition, deleting is reversible for 30 days. "Delete application" (list, detail page, bulk) moves an application, with its emails, notes and people edits, to Settings, Recently deleted, from where it can be restored. It is hidden everywhere else, but it is still in Export data and the backup file until it is erased. Resumes and cover letters wait in Recently deleted for 30 days too. After 30 days, or on "Delete now", its emails' content is erased for good. "Delete for good, keep emails in Needs review" and "Not an application" stay immediate and permanent. Copy and the privacy page must never say that deleting erases the content at once.
- Hosted edition, the browser is the only copy, so the product says so and helps: it asks the browser to keep the data, reminds the person to back up after 14 days without a JSON export (CSV doesn't count), and offers an optional backup file in browsers that can write to one (Chromium). It can be installed as an app, but there is no service worker and no offline copy: it needs the network to read mail and job boards.
- The calendar's events carry a day, not a time. Interview days are guessed from email text and can be wrong or missing, so they are labelled "Interview" and link to the application. Weeks start on Monday.
- Hosted edition login and setup: one-click login that also connects the mailbox (people can decline mail and log in without it); a guided setup page at `#/setup` where the owner follows numbered console steps, pastes the two app IDs and commits a generated `web/site-config.json` (the IDs are public by design; a build-time environment value still overrides the file); a copyable invite message for test users; and an offer, never automatic, to bring applications saved in demo mode in this browser into the account, with the earlier copy removed only on request.
- No em-dashes in UI copy.

## Brand Commitments
- Visual direction is pinned by the user: **Wealthsimple's styling**, taken from the `use-ws-styling` prototype primer (light grey ground, raised near-white cards at 20px, pill buttons with glass gradients on Primary, Lucide icons, one sans typeface, sentence case, no uppercase, no underlined links, no tabular numbers).
- The app keeps its own name, "Job Tracker". It does not use Wealthsimple's name, logo or wordmark. Wealthsimple Sans Display is proprietary and is not shipped: the stylesheet names it first so a device that has it uses it, and the self-hosted Figtree covers every other device.

## Evidence on Hand
The styling comes from the `use-ws-styling` primer in the `product-design` plugin: a hand-distilled approximation that names tokens and approximate values, not the real design system or a spec. It replaces an earlier warm serif look that was read from unofficial third-party references. Where this app departs from the primer, DESIGN.md says so (for example the slightly stronger inactive background). Status is never shown with emoji. No imagery assets exist.

## Product Principles
1. Facts first: a status, a date, and a source email are always one click apart.
2. Calm over clever: the user checks this while anxious about outcomes; nothing should shout.
3. Private by construction: mail is read only by the user's own device (a local server on their PC, or their browser), read-only unless the user turns replying on, with no server of ours in the path and no external services beyond Google, Microsoft, Anthropic (only if the user adds their own key and presses Convert) and the sources the user adds.
4. Everything is reversible and visible: filters show, manual stages say they were set by the user.

## Accessibility & Inclusion
WCAG AA contrast in light and dark, visible keyboard focus, color never the only signal, full keyboard operation, text that follows browser text size, 44px touch targets on touch screens.
